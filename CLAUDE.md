```bash
npm run dev      # Dev server on http://localhost:3001
npm run build    # Type-check and export the static site to out/
npm run lint     # ESLint (flat config in eslint.config.mjs)
npm start        # Serve out/ locally (run a build first)
```

## Architecture

A **statically exported** Next.js 16 portfolio (`output: 'export'` in next.config.js). `.github/workflows/deploy.yml` publishes it to GitHub Pages at www.matwenger.design (`public/CNAME`) on every push to `main`: `npm ci`, `npm run lint`, `next build`, then upload `out/`. There is no server runtime, so no route handlers, server actions or runtime revalidation. Images are served unoptimized: compress media before committing it.

### Content system
Each project is `content/projects/<id>.md`. Frontmatter: `title`, `description`, `cover`, `tags`, `year`, `order` (sort within a year), `role`, `company`, `videos` (local `src` + `thumbnail` + optional `captions`, or `type: youtube` with an `id`), `gallery` (`src`, `alt`, optional `caption` and `ratio`) and `caseStudy`. `lib/get-project-content.ts` parses it with gray-matter and renders the body with `marked` (links limited to safe schemes). `caseStudy` is validated by the zod schema in `lib/project-case-study.ts`; its media references are 1-based positions in `gallery` and `videos`. Invalid frontmatter fails the build and names the file. Projects sort by year (newest first), then `order`, then id. Media lives in `public/images/projects/<id>/main/`, `gallery/` and `video/`.

### Routes
- `/` — `components/home/immersive-landing.tsx`: hero and career terminal (`lib/data/hero.ts`), four featured projects hardcoded in `selectedProjects`, how I work and impact metrics (`lib/data/workflow.ts`), testimonials (`lib/testimonials-data.ts`), story and career (`lib/data/experience.ts`), contact
- `/v1` — noindex alias of `/`
- `/projects` — all projects
- `/projects/[id]` — `CaseStudyTemplate` when the project has `caseStudy` (all do today), otherwise the older `ProjectContent` view
- `/about` — portrait, personality scales, narrative and journey (`lib/data/about.ts`)
- `/lab` — static list of external prototypes (`components/lab/lab-projects-data.ts`)
- `/design-system` — noindex living style guide, in French
- `/sitemap.xml` — generated by `app/sitemap.ts`

### Design system
`docs/design-system.md` (in French) is the reference. `app/design-tokens.css` holds the tokens and three section contexts selected with `data-studio-theme="ink" | "paper" | "acid"`; ink is the default. There is no light/dark mode. Shared components live in `components/design-system/` (PageShell, PageIntro, TextLink, Tags, GalleryGrid, GalleryCard, MediaFrame, MediaFigure, MediaGallery, TraitScale, SiteHeader, SiteFooter) and are styled with CSS modules. `components/ui/` keeps only the shadcn/ui primitives in use; add others with the shadcn CLI when needed. Fonts: Inter (sans), Fraunces (serif accents), JetBrains Mono (labels) via `next/font`. Animation uses Framer Motion and must respect `prefers-reduced-motion`.

### Key conventions
- Path alias `@/*` maps to the repository root
- Page-specific components live in `components/<section>/` (e.g. `components/home/`, `components/projects/`)
- Builds fail on TypeScript errors, and CI fails on lint errors
- `public/mockups/` holds standalone design-direction pages, marked noindex

## Skill routing

When the user's request matches an available skill, invoke it via the Skill tool. When in doubt, invoke the skill.

Key routing rules:
- Product ideas/brainstorming → invoke /office-hours
- Strategy/scope → invoke /plan-ceo-review
- Architecture → invoke /plan-eng-review
- Design system/plan review → invoke /design-consultation or /plan-design-review
- Full review pipeline → invoke /autoplan
- Bugs/errors → invoke /investigate
- QA/testing site behavior → invoke /qa or /qa-only
- Code review/diff check → invoke /review
- Visual polish → invoke /design-review
- Ship/deploy/PR → invoke /ship or /land-and-deploy
- Save progress → invoke /context-save
- Resume context → invoke /context-restore
- Author a backlog-ready spec/issue → invoke /spec
